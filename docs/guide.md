# 教程食用指南

本教程的每一章都是相对独立的资料导航，但你不需要也不可能一口气读完。这一页给出贯穿全部章节的建议学习路线，以及每一步"做到什么程度可以往下走"的判断标准。

## 建议学习路线

**第 0 步：开荒（第 1 周）**

1. [比赛与电控组简介](about.md) — 知道自己在为什么而学
2. [如何寻找资源](resources.md) — 学会自己找资料，这是受用最久的一课
3. [如何配置软件环境](env-setup.md) — 装好工具，扫清第一道坎

**第 1 步：C 语言（约 1 个月）**

4. [C 语言学习](c-lang.md) — 一切的地基。学到指针与内存模型吃透即可，别追求面面俱到

**第 2 步：单片机入门（约 1 个月）**

5. [STM32 开发基础](stm32.md) — 从点灯开始，每个外设都在实板上跑一遍

**第 3 步：让机器人动起来**

6. [通信协议](comm.md) — UART / CAN 是与电机、上位机对话的语言
7. [常用模块](modules.md) — IMU、OLED、舵机，边用边学
8. [RTOS](rtos.md) — 任务多了之后，让代码结构化起来
9. [电机控制](motor.md) — 电控组的核心技术，从有刷电机调速练到 PID

**最后：综合项目**

10. [综合项目（电赛/校内赛小车）](project.md) — 把前面所有知识拼成一辆车，也是培训的验收

**贯穿全程的三件事**

- [Git 与工程化](git.md) — 从写下第一行代码起就用它管理，别等到"学完"才开始
- [数据结构与算法](dsa.md) — 不急于一时，每周保持一点量，细水长流
- [调试方法](debugging.md) — 不需要专门学，每次遇到问题回头翻，用着用着就会了

## 几条建议

- 每一步的判断标准很简单：**能动手做出对应的东西**，就往下走。不用等"全部学完"才开始做项目
- 以敲代码为主，看教程为辅；看懂了和写出来了是两回事
- 卡住是常态，先自己搜，搜不到就来培训群里问——提问前说清楚"做了什么、期望什么、实际发生了什么"

## 最后，一些鼓励的话

每个人都是从一块点不亮的开发板和满屏的报错开始的，包括现在教你的人。嵌入式学习的曲线前期陡、后期平——前两个月你会觉得什么都很陌生，但跨过点灯、串口、电机转动这几个坎之后，路会越走越顺。

别担心自己基础差，大一完全来得及；也别担心问题太简单不敢问，队里没人会笑话一个认真提问的新生。真正的分水岭不在天赋，而在你是坚持把每个小东西做出来，还是收藏了一堆教程就当作学会了。

期待在实验室见到你，期待第一辆由你亲手点亮的小车。
