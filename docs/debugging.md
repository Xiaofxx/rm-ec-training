# 调试方法

> 这或许是最折磨也是最耗时的一个阶段。。。

嵌入式调试能力直接决定开发效率：同一个问题，会调试的人十分钟定位，不会的人烧一下午板子。

## 调试软件选择

* **Keil**：可以编译烧录，调试，且拥有强大的调试能力，网上资源和教程丰富，缺点是没有可视化曲线等界面
* **ozone**：队内统一使用ozone进行调试，资料相较于Keil等软件较少，这里可以看学长写的文档：
* Vofa+：自行B站搜索教程即可

## 串口打印

- printf 重定向：通过printf用串口发送相关的信息，用串口调试助手等提供上位机
- 串口上位机：[VOFA+](https://www.vofa.plus/) — 支持波形绘制，调 PID 看曲线。

## 日志系统

强烈建议在任何运行的程序上都引入一个日志系统，可以在调试器当中获得系统的实时运行信息，

这里有很多方式：

* 用上述的串口打印，在程序运行的代码中插入printf打印一些关键的变量，利用Vofa+等上位机观察

* 若使用ozone调试，建议移植SEGGER公司下的RTT日志，结合ozone使用

  [工程调试利器：RTT（Real-Time Transfer）保姆级使用教程_rtt调试-CSDN博客](https://blog.csdn.net/qq_38364548/article/details/154431687)

## 在线调试（断点）

- Keil / ozone均支持断点、单步、观察变量、外设寄存器视图，配合 ST-Link / DAP-Link 通过 SWD 连接目标板。
- 注意：调试实时性代码（如电机闭环，使用RTOS）时断点会破坏时序，此时优先用打印 / 波形。

## 仪器测量

- **逻辑分析仪**— 抓 UART / I2C / SPI / CAN 波形，对照协议时序图定位通信问题（与"通信协议"章配合）。
- **示波器** — 看 PWM 波形、驱动信号、电平波形等，可以用来排查硬件问题。

## 无线调试

可以购买Daplink这种无线调试器，方便远程调试，不过目前看来依旧不如有线调试稳定
