# 调试方法

> 这或许是最折磨也是最耗时的一个阶段。。。

嵌入式调试能力直接决定开发效率：同一个问题，会调试的人十分钟定位，不会的人烧一下午板子。本章按硬件 / 软件两条线组织，工具链（IDE 与调试器）的选型见[开发方式](dev-workflow.md)章。

## 硬件调试

[硬件调试](debug-hardware.md) — **万用表测通断**（排查供电与断线的第一步）、**线材焊接**（排针、电源线，焊不好赛场上就"突然断电"）、**示波器/逻辑分析仪看波形**（硬件问题的终极排查手段）。

## 软件调试

不打断程序运行的日常手段与在线调试，按工具分三篇：

- [Ozone 调试方法](debug-ozone.md) — **队内统一使用**。环境配置、烧录调试、窗口介绍（Call Stack / Watched Data / Timeline 实时曲线等）、注意事项，队内完整上手文档
- [Keil 调试](debug-keil.md) — 断点、单步、Watch、外设寄存器视图，入门最省事
- [其他调试工具](debug-tools.md) — 串口打印、[VOFA+](https://www.vofa.plus/) 看曲线、SEGGER RTT 日志系统

!!! note
    调试实时性代码（如电机闭环，使用 RTOS）时断点会破坏时序，此时优先用串口打印 / 波形。
