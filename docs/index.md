# 欢迎

这里是苍穹战队电控组培训资料的入口，面向准备加入战队电控组的新成员。本教程梳理一条从零基础到能独立完成项目的学习路线，并为每一站配好资料。本教程内容定位是**学习路线 + 资料导航**（不写知识点讲解，只给推荐教程、资料链接和学习建议），具体的知识点请自行学习。

> 后续会有正式的培训，具体线上/线下培训以实际为准，目前本网站以指导大家自学为主

## 培训目标

- 掌握嵌入式开发的基本技能栈：C 语言 → STM32 → 通信协议 → RTOS → 电机控制（无需严格线性推进，可同时进行）
- 能独立完成一个小型机器人/小车项目（见"综合项目"章）
- 通过队内考核，正式加入电控组，进入项目组参与比赛开发

## 教程食用指南

本教程的每一章都是相对独立的资料导航，但你不需要也不可能一口气读完。这一页给出贯穿全部章节的建议学习路线，以及每一步"做到什么程度可以往下走"的判断标准。

### 建议学习路线

**第 0 步：开荒**

1. [比赛与电控组简介](about.md) — 了解比赛以及技术定位
2. [如何寻找资源](resources.md) — 学会自己找资料，这是受用最久的一课
3. [如何配置软件环境](env-setup.md) — 装好工具，扫清第一道坎

**第 1 步：C 语言**

4. [C 语言学习](c-lang.md) — 一切的地基。学到指针与内存模型吃透即可，别追求面面俱到

**第 2 步：单片机入门**

5. [STM32 开发基础](stm32.md) — 从点灯开始，每个外设都在实板上跑一遍

**第 3 步：让机器人动起来**

6. [通信协议](comm.md) — UART / CAN
7. [常用模块](modules.md) — IMU、OLED、舵机，边用边学
8. [RTOS](rtos.md) — 任务多了之后，让代码结构化起来
9. [电机控制](motor.md) — 电控组的核心技术，从有刷电机调速练到 PID

**最后：综合项目**

10. [综合项目（电赛/校内赛小车）](project.md) — 把前面所有知识拼成一辆车，为后续校内赛做准备

**贯穿全程的事**

- [Git 与工程化](git.md) — 从写下第一行代码起就用它管理
- [硬件调试](debug-hardware.md)、[软件调试](debug-ozone.md) — Debug阶段会遇到非常多的问题，这里只有具体的工具和配置，建议可以线下来答疑解决问题

### 几条建议

- 每一步的判断标准很简单：**能动手做出对应的东西**，就往下走。不要认为，我脑子里记住这个概念了就可以，一定要实际上手做，有了实际的现象才认为你会了，当然同时能懂底层和原理是最好的

- 以敲代码为主，看教程为辅；看懂了和写出来了是两回事

- 卡住是常态，先自己搜，搜不到就来培训群里问——提问前说清楚你的具体问题背景"什么环境下，遇到了什么问题，你不懂的点在哪"，这样大家解决问题也更高效一点，不要害怕提问！学长学姐都很热心都会解答你的疑问，学会提问解决问题也是非常重要的能力

  [【中科大RM电控合集】每个新领域的学习者都要看一看的东西](https://www.bilibili.com/video/BV1w3411o7Y3?vd_source=0ec807ca37217dda15dcd3c1863ba0c9)

### 最后，一些鼓励的话

每个人都是从一块点不亮的开发板和满屏的报错开始的，包括现在教你的人。嵌入式学习的曲线前期陡、后期平——前两个月你会觉得什么都很陌生，但跨过点灯、串口、电机转动这几个坎之后，路会越走越顺。

别担心自己基础差，大部分人都是0基础；也别担心问题太简单不敢问，队里没人会笑话一个认真提问的新生。真正的分水岭不在天赋，而在你是坚持把每个小东西做出来，还是收藏了一堆教程就当作学会了。

加油！电控组期待你的加入！
